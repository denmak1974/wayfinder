# Security Policy

## Supported versions

During alpha, only the most recent release receives security fixes.

## Reporting

Do not open a public issue for a vulnerability or personal-data exposure. Until a dedicated security mailbox is established, use GitHub private vulnerability reporting in this repository.

Include the affected version, reproduction steps, impact, and suggested mitigation. Use synthetic data and remove access tokens, personal schedules, images, and identities.

Maintainers aim to acknowledge reports within two working days, provide an initial severity assessment within five, and coordinate disclosure after a fix is available. Good-faith research that avoids privacy violations, persistence, denial of service, and data destruction is welcomed.

See [Privacy and Security Architecture](docs/security/PRIVACY-THREAT-MODEL.md).
